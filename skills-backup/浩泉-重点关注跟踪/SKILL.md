# 重点关注跟踪系统

## 依赖

本 Skill 依赖 `skills/浩泉-报告排版引擎/`（报告渲染管线）。如果该目录不存在，提示用户先安装 浩泉-报告排版引擎。

## 数据文件

跟踪数据存储在 `skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json`。
如果该文件不存在，使用本 Skill 目录下的 `data/浩泉-重点关注跟踪.json` 模板创建它，填入当前时间戳。
如果模板也不存在，按下方条目字段定义创建空初始文件。

> 兼容旧版：如果 `skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json` 不存在但 workspace 根目录有 `浩泉-重点关注跟踪.json`，
> 将其移动到 `skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json`，并告知用户已迁移。

## 首次使用（AI 自引导）

AI 首次触发本 Skill 时，检查 `skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json` 是否存在。
如不存在，从本目录的 `data/浩泉-重点关注跟踪.json` 复制模板，填入当前时间戳。对用户透明，无需告知。

## 概述

"重点关注"是用户的自选股/板块/概念动态跟踪机制。本 Skill 负责：
- **交互式管理**：对话中添加/删除/查看重点关注标的
- **每日自动化分析**：行情技术面、公告、研报、新闻、重大事项
- **HTML 报告生成**：Markdown → md2html.py（与每日复盘共用同一套渲染管线）

## 触发规则

| 用户输入模式 | 动作 |
|-------------|------|
| `把XX加入重点关注` / `关注XX` / `加入跟踪XX` | → 执行 **添加操作** |
| `XX不关注了` / `XX短期不看了` / `移除XX` | → 执行 **软删除操作** |
| `重新关注XX` / `恢复XX跟踪` | → 执行 **恢复操作** |
| `看看重点关注` / `我的自选` / `跟踪列表` | → 执行 **查看操作** |
| `立即检查重点关注` / `跑一次跟踪` | → 执行 **手动全量检查** |

## 数据文件详细说明

**`skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json`** — 结构化跟踪列表。所有读写操作均指向此路径。

### 条目字段

```json
{
  "id": "stock-000001",           // 唯一标识：type-code 或 type-name
  "type": "stock",                // stock | sector | theme
  "code": "000001",               // 证券代码（theme 可为空）
  "setcode": "0",                 // 市场代码（theme 可为空）
  "name": "平安银行",              // 显示名称
  "addedAt": "ISO时间戳",          // 添加时间
  "addedReason": "用户关注原因摘要", // 来自对话总结
  "tags": ["AI-PCB材料", "电子树脂"],  // 精确细分概念，不用泛泛标签
  "conceptChain": "电子树脂 → CCL覆铜板 → PCB → AI服务器",  // 产业链定位
  "status": "active",             // active | inactive
  "priority": "core",             // core | watch（超20个时强制分层）
  "lastChecked": "YYYY-MM-DD",    // 最近检查日期
  "representativeStocks": [],     // sector/theme 专属：代表龙头股
  "relatedStocks": [],            // theme 专属：相关标的
  "relatedSectors": []            // theme 专属：相关板块
}
```

### 条目数阈值

- ≤20 个 active 标的：全部按 core 处理
- >20 个 active 标的：**必须提示用户**标记哪些是 core（全维度），哪些是 watch（仅异动+重大新闻）

## 操作一：添加标的（ADD）

### 触发

用户说"把XX加入重点关注"或类似表述。

### 执行流程

**Step 1 — 搜索对话上下文**
- 使用 `feishu_im_user_search_messages` 或已有对话历史，搜索最近包含该标的名称/代码的消息
- 提取：用户为什么提及它、讨论的核心观点、关注原因

**Step 2 — 识别标类型并补全信息**
- 调用 `tdx_lookup_stock` 判断是股票、板块还是指数
- 如果是股票：获取完整 code + setcode + name
- ⚠️ **关键步骤：产业链/概念定位**
  - 调用 `tdx_api_data` entry="TdxSharePCCW.tdxf10_gg_rdtc" fixedTag="zttzbkz" 获取热点题材板块族谱
  - 调用 `tdx_indicator_select` message="XX 概念板块" 获取概念归属
  - 结合用户提供的产业知识，确定标的的**产业链位置**（上游/中游/下游，具体环节）
  - 写入 `conceptChain` 字段（如：电子树脂 → CCL → PCB → AI服务器）
  - 写入 `tags` 字段（精确到具体细分概念，而非泛泛的"新材料""化工"）
  - **如果无法确定产业链定位 → 主动询问用户**
- 如果是板块：获取板块代码（880xxx / 881xxx），并获取板块内龙头股
- 如果都查不到（题材/方向）：标记为 theme 类型

**Step 3 — 总结要点**
基于对话内容，提炼 1-2 句话的"关注原因摘要"，写入 `addedReason`。

**Step 4 — 比对去重**
- 读取 `skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json`
- 检查同名/同代码是否已存在
- 已存在且 active → 告知用户"已在重点关注中"，可选择更新摘要
- 已存在且 inactive → 提示是否恢复
- 不存在 → 添加新条目

**Step 5 — 写入并确认**
- 更新 JSON 文件
- 告知用户添加结果（名称、类型、关注原因摘要）
- 如果 active 数超过 20，提示分层

---

## 操作二：软删除（REMOVE）

### 触发

用户说"XX不关注了"、"XX短期不看了"。

### 执行流程

1. 在 `skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json` 中找到对应条目
2. 将 `status` 改为 `"inactive"`
3. 记录 `removedAt` 时间戳
4. 告知用户：已停止跟踪，历史报告保留，两周后自动清理

---

## 操作三：恢复（RESTORE）

### 触发

用户说"重新关注XX"。

### 执行流程

1. 在 JSON 中找到 inactive 条目
2. 将 `status` 改回 `"active"`
3. 清除 `removedAt`
4. 告知用户恢复成功

---

## 操作四：查看列表（LIST）

### 触发

用户说"看看重点关注"或类似表述。

### 执行流程

1. 读取 `skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json`
2. 按 type 分组展示（个股 / 板块 / 题材方向）
3. 显示每个标的：名称、优先级、最近检查日期、关注原因摘要
4. 统计：active 数量 / core 数量 / watch 数量
5. 如果有 inactive 条目，询问是否需要清理

## 操作五：手动/自动全量检查（CHECK）

### 触发

- 手动：用户说"立即检查重点关注"
- 自动：Cron 每日定时（默认 18:30）

### 执行流程

**Step 0 — 准备工作**
1. 读取 `skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json`，获取所有 `status=active` 条目
2. 按 `priority`（core 优先）+ `type` 排序
3. 按 `maxItemsPerBatch`（默认 5）分批
4. 如果当天已生成报告（`分析报告汇总/YYYY-MM-DD/` 下存在含"重点关注"的 HTML 文件且不是手动触发），跳过

**Step 1 — 逐批拉取数据**

对每个标的，按类型拉取：

#### 个股（type=stock）

**行情技术面：**
- `tdx_kline` period=4 wantNum=120：获取日线数据
- `tdx_quotes` hasCalcInfo=1 hasHQInfo=1 hasExtInfo=1 hasProInfo=1：实时行情
- 计算：MA5/MA10/MA20/MA60 均线排列（多头/空头/交叉）
- 计算：MACD（DIF/DEA/柱状图），判断金叉/死叉/背离
- 计算：成交量环比变化（放量/缩量）
- 识别：近期支撑位（前低）、压力位（前高）
- 资金流向：`tdx_api_data` entry="TdxSharePCCW.tdxf10_gg_jyds" fixedTag="zjlx"：资金流入流出

**公告动态（近3日）：**
- `wenda_notice_query`：symbol=代码，bdate=3天前，edate=今天
- 重点标记：业绩预告、增减持、重大合同、资产重组

**研报动态（近7日）：**
- `wenda_report_query`：symbol=代码，bdate=7天前，edate=今天
- 提取：券商名称、评级变化、目标价调整、核心观点

**重大事项：**
- `tdx_api_data` entry="TdxSharePCCW.tdxf10_gg_gbjg" fixedTag="xslt"：限售解禁
- `tdx_api_data` entry="TdxSharePCCW.tdxf10_gg_fhrz" fixedTag="fh"：分红实施

**新闻（近3日）：**
- `wenda_news_query`：name=标的名称，bdate=3天前

#### 板块（type=sector）

**指数走势：**
- `tdx_kline`：板块指数日线/周线
- 计算技术指标（同个股）

**板块新闻/政策/会议：**
- `wenda_news_query`：name=板块名称，bdate=3天前，keywords=政策,会议,利好,利空

**龙头股摘要：**
- 对 `representativeStocks` 中的龙头股拉取行情快照
- 统计：涨跌家数、板块内涨幅前三
- 每只龙头股 1 句话表现总结

#### 题材/方向（type=theme）

**新闻/政策动态（近7日）：**
- `wenda_news_query`：keywords=题材关键词
- 筛选高质量来源

**代表性标的动态：**
- 对 `relatedStocks` 中的标的拉取行情
- 汇总方向内代表性标的的表现趋势

**Step 2 — 生成分析判断**

对每个标的给出结构化判断：

```

| MACD | DIF: X, DEA: X | 金叉/死叉/零轴上方/下方 |
| 成交量 | XX万手 | 放量/缩量（环比+X%） |
| 支撑位 | XX.XX | 近N日低点 |
| 压力位 | XX.XX | 近N日高点 |
| 资金流向 | 净流入/流出 XX亿 | — |

> 一句话技术判断：[趋势方向 + 关键信号 + 风险提示]

### 📋 公告（近3日）
- [日期] 公告标题 → 一句话影响判断
- （无公告则写"无重要公告"）

### 📝 研报（近7日）
- [日期] [券商] [评级] [目标价] → 核心观点摘要
- （无研报则写"无最新研报"）
```

**Step 3 — AI 写入轻量化 Markdown + md2html 渲染**

⚠️ **v4.0 架构升级：放弃复杂 JSON → PDF 管道，改用 Markdown → HTML（与每日复盘同一套管线）。**

**设计原则：**
- AI 直接写 Markdown，所有分析推理都在 Markdown 中完成
- 不依赖 generate_report.py 做数值计算或排版
- 不再需要填入 120 个收盘价到 JSON
- 板块/个股总览表由 AI 直接在 Markdown 中写（不会出现 "0.00% — — —" 信息缺失）
- 操作参考不再被截断（Markdown 表格自然换行）

**执行流程：**

1. AI 基于 Step 1-2 数据，完成全部分析判断（均线、MACD、资金、趋势、驱动、风险、操作参考），直接写入 Markdown

2. 写入文件：`temp_focus_YYYYMMDD.md`（workspace 根目录）

3. 运行转换脚本：
   ```
   python skills/浩泉-报告排版引擎/md2html.py temp_focus_YYYYMMDD.md
   ```
   输出自动写入 `分析报告汇总/YYYY-MM-DD/` 目录

4. 删除临时 `temp_focus_YYYYMMDD.md`

## 自动清理机制（Cron 触发）

每两周（14天）执行一次清理：

1. 读取所有 `status=inactive` 且 `removedAt` 超过 14 天的条目
2. 从 `skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json` 中永久删除
3. **不删除**已有的历史 PDF 报告
4. 在当天的每日报告中记录清理日志

---

## 异动通知规则

每日检查完成后，以下情况需要**主动通知用户**（通过当前对话或消息）：

- 涨停 / 跌停
- 单日涨跌幅超 ±7%
- 成交量放大超 3 倍
- 重大利好/利空公告
- 研报评级上调/下调
- MACD 关键信号变化（金叉/死叉/顶背离/底背离）

通知格式：简短摘要，不要完整报告。

## 注意

- 所有 API 调用保持合理间隔，避免并发过大
- 分批执行中如遇单批超时，记录进度后可续传
- 市场休市日（周末/节假日）自动跳过行情分析，只检查公告/新闻

## 建议的 HEARTBEAT.md 配置

如需每日自动检查，在 workspace 根目录的 `HEARTBEAT.md` 中添加：

```markdown
### 收盘后 — 重点关注全量检查（交易日 17:30-19:00）

防重复：检查 分析报告汇总/YYYY-MM-DD/ 下是否已有今日重点关注 HTML 文件。

执行步骤：
1. 读取 skills/浩泉-重点关注跟踪/data/浩泉-重点关注跟踪.json，筛选 status=active
2. 判断当日是否为交易日
3. 分批获取数据（每批 5 个）：行情 + K线 + 新闻 + 公告 + 研报
4. AI 分析：均线、MACD、量价、资金、驱动、风险
5. Markdown → python skills/浩泉-报告排版引擎/md2html.py → 删除临时 md
6. 更新 lastChecked
7. 异动通知
```

此配置为可选项，由用户自行决定是否添加，不包含在 Skill 安装流程中。
